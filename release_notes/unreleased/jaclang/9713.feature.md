- **byLLM: a configurable timeout for non-streaming `by llm()` calls**: `[byllm.call_params] timeout` bounds a single non-streaming request in seconds, overridable per `Model(timeout=...)` and per `by llm(timeout=...)`. Defaults to `600.0`, so nothing changes until a project lowers it, and `0` drops the bound. Outliving it raises `LLMTimeout`, which still subclasses `litellm.Timeout` so retries and existing `except` clauses keep working. See [Request Timeout](../../reference/plugins/byllm.md#request-timeout).
- **byLLM: a non-streaming call no longer retries twice inside the provider**: LiteLLM's client was left at its own default, so each byLLM attempt spent the timeout up to three times over and the bound meant roughly a third of what it said. byLLM owns the retry loop, so the provider call now passes `num_retries=0`.
- **byLLM: the `http_client` transport honors the request timeout**: it hardcoded 60s and posted its parameter dict verbatim, which also broke the streaming path by sending a non-serialisable `httpx.Timeout` in the body.
